# せーの！神輿バトル v2 — 再設計書

## 1. v1 の何が弱かったか

| 観点 | v1 の状態 | 問題 |
|---|---|---|
| タップの密度 | 1試合＝1ラウンド1回×3ラウンド＝**3タップ** | 1回押したら5秒待って、結果を5秒見るだけ。遊んでいる時間が短い |
| 競技性 | 「100ms以内に何人揃ったか」だけ | 上手い人と下手な人の差が出にくい。練習する理由がない |
| ぶつかり合い | 勝敗が決まった**後**に再生される映像 | プレイと演出が切り離されていて、自分たちの力で押している実感がない |
| 相手の存在 | 最後にパワーの合計を比べるだけ | 対戦中に相手の強さが見えない。逆転のドラマがない |
| 3D | 神輿は作り込みがあるが、質感がのっぺり | 凹凸情報（法線）・光のにじみ・環境の映り込みが無く、色も白く浮いていた |
| アバター | 箱と円柱の小さな人形 | 自分の分身として愛着が湧かない |

## 2. v2 の核：「練り合い」

実際の神輿は「ワッショイ」「セイヤ」の掛け声で**リズムを揃えて**担ぐ。喧嘩神輿は2基が**ぶつかり合う**。
この2つをそのままゲームにする。

### 1番（ラウンド）の流れ　※1試合＝3番

```
[番の紹介] → [拍子木の前打ち 4拍] → [担ぎ 8拍] → [せー] → [の] → [！（ぶつけ）] → [結果]
   1.4秒         数えるだけ           毎拍タップ      タップしない      全員で1回        2.6秒
```

- **担ぎ（8拍）**：太鼓の拍に合わせて毎拍タップ。画面下の「太鼓レーン」を右から流れてくる音符が、左の輪に重なる瞬間に叩く。
  - 自分の正確さ：拍とのズレ ±45ms「極」/ ±100ms「良」/ ±170ms「可」/ ±250ms「惜」
  - 連の揃い：その拍で**0.1秒の窓に入った人数**（v1 の判定をそのまま拍ごとに使う）
  - 拍の点数 ＝ 揃った人たちの正確さの合計 ÷ 連の人数 × 10（最大10点。人数の多い連が有利にならない）
  - **勢い（コンボ）**：6割以上揃った拍が続くと勢いが上がり、点数が最大1.48倍
  - 連打しても1拍1回しか数えない（最初の1回。早すぎる連打はむしろ損）
- **せーの！（ぶつけ）**：8拍の後、太鼓が止まり笛と「せー」「の」の声だけになる。
  **太鼓の無い3拍目**に全員で1回タップ。体内のリズムと連の一体感だけが頼りの一撃。
  - 揃った割合で v1 と同じ判定（MIRACLE / PERFECT / GREAT / NICE / 空振り）
  - 点数 ＝ 揃った割合 × 正確さ × 30 ×（1 ＋ 勢い×0.05）── 担ぎで勢いを溜めるほど一撃が重くなる
- テンポは番ごとに上がる：一番 96 → 二番 108 → 三番 120（BPM）

### 押し合い（リアルタイムの対戦感）

- 拍ごとに両連の点数が出て、**押し合いゲージと3Dの神輿の位置がその場で動く**
- 相手の担ぎ手の動きもリアルタイムに見える（揃っていない連の神輿はガタガタ傾く）
- 3番の合計点が高い連の勝ち（同点ならぶつけの合計）。最後に負けた神輿は押し出される

### タップ数と試合時間

1番あたり 担ぎ8＋ぶつけ1＝9タップ、1試合で**27タップ**（v1 は3タップ）。1試合 約45秒。

### 稽古モード

ログイン無しで遊べる1人練習。サーバーを使わず、画面側だけで採点する（コインは出ない）。
リズムの感覚を掴んでから対戦に入れる。

## 3. 変えていないもの（CLAUDE.md のルール）

- **サーバー権威**：拍の判定・点数・勝敗・コイン・ガチャはすべて server.js。画面側の「極・良」表示は即時の手応え用の見た目だけで、点数には使わない
- **コイン**：勝利 +20、シンクロ貢献 +5×（ぶつけで揃いに入れた番の数）。v1 の「シンクロ成功ラウンド」と同じ意味
- **判定しきい値**：MIRACLE≥1.0 / PERFECT≥0.8 / GREAT≥0.6 / NICE≥0.4
- **神輿9様式**・**衣装ガチャの15品とレア度・排出率**
- **ギャンブル用語なし**
- ログイン・QR招待・店舗QR・外部連携API・Webhook・保存の仕組み

## 4. 変えたもの（所有者の確認が必要な点）

| 項目 | v1 | v2 | 理由 |
|---|---|---|---|
| タップ受付時間 `TAP_DURATION_MS=5000` | 合図から5秒 | 廃止。拍ごとに ±250ms（`HIT_WINDOW_MS`） | リズム判定に置き換えたため |
| 通信メッセージ | round / tap / roundResult / battle | 同じ名前を維持し中身を拡張。拍ごとの `beat` を追加 | 押し合いをリアルタイムに見せるため |
| 結果発表前の広告 | ぶつけ合いの直前に8秒 | **削除**（試合前の広告は v1 のまま残す: 15秒・5秒でスキップ可） | ぶつけ合いが試合中に起きるようになり、直前で止めると熱が冷めるため |
| 敗北時の「応援予想」 | ランダムで当たり外れ | **削除**、代わりに結果画面で試合の振り返り（番ごとの判定・自分の成績・連の中の貢献） | 予想の結果が実際の試合と無関係だったため |
| 画面ファイル | index.html 1本（約3,700行） | index.html＋`public/js/` に役割別7本 | 3Dが大きくなり1本では直しにくいため |
| 依存関係 | jsdom が本番用にも入っていた | 開発用だけに整理 | 本番の導入を軽くするため |

## 5. 3D の設計

- **質感**：金具の彫金（七宝つなぎ）・漆の艶・白木の木目・布の織り目・石畳・玉砂利を、すべて**色＋凹凸（法線）＋粗さ**の3枚で生成
- **光**：夕暮れの空と提灯から作った環境マップ（金が祭りの夜を映す）＋光のにじみ（ブルーム）＋映画調の色調補正（影は青紫・明部は暖色）＋周辺減光＋粒子感
- **色の扱い**：色指定を正しく「光の計算用の色」に変換（v1 の白く霞む見た目の原因だった）
- **会場**：参道の石畳と玉砂利、朱の大鳥居（扁額「祭禮」）、拝殿（障子から漏れる灯り・大提灯・唐破風）、石灯籠、結界の注連縄と紙垂、献灯の提灯棚、屋台（のれん）、頭上の提灯の綱、観客、杉木立、遠山、夕焼け、花火
- **神輿**：v1 の正しい比率（台輪1.52・反り屋根・蕨手・鳳凰）を引き継ぎ、正面を担ぎ棒の向きに合わせ直した。屋根の稜線は屋根の曲面に沿わせ、正面に三つ巴の紋、鳳凰は羽根の縁が波打つ翼。勝ち進むほど提灯・幕・瓔珞が増える
- **担ぎ手**：骨格つきの人形（20本の骨）。法被（柄・背紋・襟）・腹掛け・帯・股引・地下足袋・ねじり鉢巻・普段と掛け声の2つの表情。1人を1回の描画で描く（約3,300三角形）
- **動き**：担ぎ手は**実際のタップのタイミングで**神輿を突き上げる。揃えば神輿がまっすぐ跳ね、ばらけると傾いて揺れる。房や提灯は遅れて揺れる
- **ぶつかり**：「せー」で下がって溜め、「の」で踏み込み、「！」で激突（火花・砂煙・スローモーション・画面の揺れ・色ずれ）。判定が届くまで鍔迫り合いで押し合い、届いた瞬間に勝った側が押し込む
- **決着**：負けた神輿は押し出されてうなだれ、勝った連は神輿を頭上に差し上げ、紙吹雪と花火
- **カメラ**：入場は鳥居の上空から舞い降りる／試合中は自分の連の斜め後ろ上（両方の担ぎ手が見える）／激突は肩越しの低い位置／決着は勝った神輿の横前
- **軽さ**：同じ素材の部品は結合して描画回数を約半分に。重い端末では自動で解像度を落とし、古い端末では光のにじみ無しの軽量表示に切り替わる

## 6. 画面の方針（2026-10 見直し）

- **ダイヤル**（web-ui-design の3軸、1〜10）：変化3／動き7／密度6。主役は3Dの境内なので、画面の部品は中央1列の左右対称にして邪魔をしない。動きは試合の演出が担う。
- **文言の決まり**：ボタン・見出し・試合中の掛け声は常体（「祭りに参加する」「太鼓に合わせて担げ」）、案内・お知らせは敬体（「〜できます」「〜してください」）。
- **読み上げ・操作**：拡大を禁止しない／押せる所は44px以上／画面が替わったら見出しへフォーカス／判定・ぶつけの結果・ガチャの結果・お知らせは読み上げる（拍ごとの点数とカウントダウンは読まない）／選択中のカードは aria-pressed／QRの画面は Esc で閉じる。
- **動きを減らす設定**（端末の「視差効果を減らす」等）：画面の揺れ・手持ち風の揺れ・スロー・強い閃光・色ずれを止め、紙吹雪と花火を1/4、振動を止める。
- **自分と相手**：色だけに頼らず、点数欄に「自」「敵」の札を付ける。揃った仲間の点は二重の輪で示す。
